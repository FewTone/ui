# 2026-10-12 · How UI libraries build component pages

## Why we did this
Before building the docs site (Phase 2), the owner wanted to know how popular UI libraries lay out their component pages. Three goals:
- FewTone UI should feel instantly familiar.
- It should stay simple.
- It should rank well in search.

Four agents checked 12 sites. Each one fetched the raw server HTML with curl, read the robots, sitemap, `llms.txt` and `.md` files, and took desktop and mobile screenshots in headless Chrome. Anything an agent could not verify is listed at the end.

## Page anatomy (what developers expect)
Almost every site follows the same order:
1. **Title.** An h1, then one sentence. The same sentence is reused as the meta description and the OG description.
2. **Live demo** directly under the title.
3. **Installation**, in two tabs:
   - CLI: a pnpm/npm/yarn/bun switcher and `npx shadcn add @ns/name`
   - Manual: install dependencies, paste the source, fix the imports
4. **Usage:** the import line, then a JSX snippet.
5. **Examples:** one heading per variant, each with its own demo.
6. **API reference:** a table of Prop / Type / Default / Description for each part. Some sites add a data-attribute table and a render-props table.
7. **Prev / next** links to the neighbouring components.

**Layout:**
- Three columns: a grouped sidebar, a content column about 640–820px wide, and an "On this page" list on the right.
- ⌘K search.
- On mobile, a hamburger menu and a dropdown for "On this page".

**AI page actions:** a "Copy page" button whose menu offers View as Markdown and Open in ChatGPT / Claude / v0. shadcn, Magic UI, Animate UI, coss, HeroUI and React Aria all have one.

### Two ways to show the demo and its code
| Style | Who uses it |
|---|---|
| **Demo with the code folded underneath** ("View code" / "Expand code") | shadcn (current), Radix, Mantine, HeroUI, React Aria; 21st.dev puts the code below |
| **Preview / Code tabs** | Magic UI, Aceternity, Animate UI, Motion Primitives, coss, Kibo |

The large general-purpose libraries have moved to folded code, and shadcn did so in its latest version. The animated libraries still use tabs.

## Best ideas worth adopting
- **Replay button** on animated demos: Magic UI, Animate UI.
- **Keyboard table** with a link to the WAI-ARIA pattern: Radix, the only site with a real accessibility section.
- **Info row** under the title (source, version and size, ARIA pattern, View as Markdown): Radix, Mantine.
- **Data-attribute table** (`[data-state]`, `[data-hovered]`): Radix, React Aria, HeroUI.
- **Collapsible prop groups** (Events, Styling, Accessibility), so long APIs stay short: React Aria.
- **Related components**, for internal linking: HeroUI.
- **Last updated** date: Animate UI.
- **Live prop controls** next to the demo: Animate UI, React Aria, Mantine. We'll do this later, driven by the Lab's `controls`.
- **Highlighted lines** in long code: React Aria.

## Where nobody delivers
- **Reduced motion:** 0 of 12 sites document it on a component page. Even the animated libraries' sources mostly ignore it.
- **Accessibility:**
  - Radix is the only site with a keyboard table.
  - React Aria has inline callouts instead.
  - coss puts its notes inside the API section.
  - The other 9 sites have nothing.
- **Complete SEO:** no site gets every basic right (see below).

## SEO and AI findings
| Item | Sites that get it right | Notes |
|---|---|---|
| Self-referencing canonical | 5 of 12 | shadcn, Aceternity, HeroUI, React Aria, 21st |
| OG image per page | 8 of 12 | Generated by Magic UI, Animate UI, Kibo, HeroUI, React Aria and 21st; per-page by shadcn (query-string OG); static per component on Aceternity. Motion Primitives' OG URL points at `localhost`. |
| JSON-LD (TechArticle / SoftwareSourceCode + BreadcrumbList) | 4 of 12 | Magic UI, Aceternity, HeroUI, 21st |
| `sitemap.xml` | 7 of 12 | Only Magic UI and 21st have real lastmod dates. The others use the build time or none. Mantine's sitemap URLs all redirect. |
| `robots.txt` | 8 of 12 | Aceternity and 21st write explicit rules for AI crawlers |
| `llms.txt` | 8 of 12 | Plus `llms-full.txt` on several |
| Markdown version of each page | 9 of 12 | Quality varies. shadcn and coss serve raw MDX. Only React Aria and 21st announce it with `<link rel="alternate" type="text/markdown">`. |
| All content in the server HTML | 6 of 12 | Partial on Mantine (the props tab is client-only), Aceternity (code), Animate UI (install command), Motion Primitives and Kibo (example code), 21st |
| A single h1, before any other heading | Most | Broken by hidden search dialogs or ad headings on Magic UI, Aceternity, Radix and 21st |
| No upsells | about 5 of 12 | Radix, Mantine, Animate UI, coss, React Aria |

**Weight:** the lightest page is Motion Primitives (about 215 KB of JS) and Mantine (about 547 KB gzip). The heaviest:

| Site | JavaScript |
|---|---|
| shadcn | ~2.6 MB brotli |
| Kibo | ~1.85 MB |
| HeroUI | ~1.3 MB |
| 21st | ~3.2 MB |
| Aceternity | one chunk of ~2.5 MB compressed, holding every component's highlighted code |

Big inline React Server Components payloads (shadcn, about 574 KB) and client-side syntax highlighting are the main causes.

## What to avoid
- Upsells inside the docs: Pro banners, sidebar ads, cart and modals.
- Headings placed before the h1.
- Content that only appears after client JS runs.
- Shipping highlighted code as JS. Highlight it on the server instead.
- Props tables that overflow sideways, and huge empty preview boxes.
- OG settings that break: a missing `metadataBase` (Motion Primitives' localhost URL) and a wrong `og:url` (Animate UI).
- Near-duplicate pages with identical titles: shadcn's three primitive "bases".
- Keyword stuffing: 21st.dev's meta keywords, coss's legacy titles.
- Redirecting old URLs without keeping their paths (originui.com → coss.com).

## What this means for FewTone UI
- Use the familiar anatomy and layout, so developers never have to hunt.
- Add our own extras:
  - an Accessibility section on every page: keyboard table, ARIA pattern and **reduced-motion behaviour**
  - Replay and a reduced-motion toggle on every animated demo
- Get every SEO basic right at once. No single site does today:
  - canonical
  - OG image per page
  - TechArticle and BreadcrumbList JSON-LD
  - a sitemap with real lastmod
  - robots
  - everything in the server HTML
  - one h1
  - `llms.txt`, plus a clean `.md` page announced with `rel="alternate"`
- Keep pages light:
  - static prerendering
  - Shiki highlighting at build time
  - no ads
- The proposed page, routes and content model are in the Phase 2 plan. The decisions will go into ADR 0007 and ADR 0008 once the owner approves.

## Addendum: beUI, the owner's design pick
The owner liked **beui.dev/components** most. It was checked on the same day.

**Pages:**
- **Index** (`/components/motion`):
  - breadcrumb, h1 "Animated React components", one sentence
  - a "New" row of cards, then a three-column grid of nested cards (a title and New badge, then an inset panel with the description; text only, no previews)
- **Component page** (`/components/motion/button`):
  - breadcrumb with a chevron; h1, the sentence and a Copy Page split button
  - then **several variants on one page**. Each variant has an h2, a file-name chip, a description, **Preview / Usage / Code** pill tabs over an open canvas, Install (CLI or Manual, bun/npm/pnpm/yarn) and an API Reference.
  - the API Reference shows the prop, its types and the default as mono chips, with a note under each.
  - **Related components** at the bottom.

**Chrome:**
- **Sidebar:** a filter row by kind; section labels with counts (Components 53, Blocks 23); New badges.
- **Header:** a three-way theme switch (light / dark / system).
- **Right rail:** a Pro ad and sponsors. FewTone UI leaves this out.

**SEO** (the strongest of all the sites checked):
- **Title:** "Button · React motion component · beUI", with a keyword-rich description.
- **Canonical:** set.
- **OG image:** generated per page (`/api/og?component=button`).
- **JSON-LD:** WebSite, Organization, SoftwareApplication, BreadcrumbList and TechArticle.
- **Sitemap:** 115 URLs.
- **robots.txt:** written for AI search bots.
- **llms.txt:** yes.

**Decision direction:** follow beUI's layout and craft in FewTone UI's colours, with two columns and no ads. It is recorded in ADR 0007 once approved.

## Could not verify
- Dropdown menu labels on Magic UI and HeroUI. They were read from the JS bundles.
- Whether Aceternity's very large chunk finishes loading in a normal session.
- How Animate UI renders its install command.
- The full list of options in Radix's styling select.
- The labels on Mantine's floating LLM widget.
- Load times. Network conditions were noisy, and the agents ran from India.
