# Command: decisions

**Status:** published (2026-10-16), built from the roadmap note "⌘K search for pages and actions", with Combobox on the same machinery. Waiting for the owner's review on the dev server.

- **What it is:** a composable command menu: inline on a page, or as a ⌘K palette in a dialog (`CommandDialog`). Parts and props follow shadcn's (which wraps cmdk): `Command`, `CommandInput`, `CommandList`, `CommandEmpty`, `CommandGroup` (`heading`), `CommandItem` (`value`, `keywords`, `onSelect`, `disabled`, `forceMount`), `CommandShortcut`, `CommandSeparator` (`alwaysRender`), `CommandDialog` (`title`, `description`, `showCloseButton`). The root keeps cmdk's `filter`, `shouldFilter`, `loop`, `label` and `value`/`onValueChange` for the highlighted item; `CommandInput` keeps `value`/`onValueChange` for the search.
- **No cmdk package** (brief: no new npm packages). The behaviour is ours, built the way Select's `searchable` mode is: the DOM is read after each render, so any markup can sit between the parts.
- **Filtering and ranking:**
  - **The score** (`commandFilter`, exported, from 0 to 1): exact match 1, the text starting with the search 0.9, a later word starting with it 0.8, anywhere 0.7, a keyword starting with it 0.6, a keyword containing it 0.5, every word of the search starting some word 0.4 ("dark theme"), and last the letters in order, the first starting a word, scored by how tight the run is (0.1 to 0.3: "stg" finds Settings, "clnd" Calendar). Requiring the first letter at a word start keeps the in-order match from finding nonsense in long names.
  - **What it matches:** the item's text (or `textValue`) and `keywords`, never `value`. cmdk matches `value`, which makes ids searchable; here `value` is only the identity onSelect receives. `CommandShortcut`'s text is left out of the item's text, so "Profile⌘P" doesn't match "p⌘".
  - **Ranking without moving nodes:** while searching, each item gets a CSS `order` from its score, and each group the order of its best item, so the best match is on top and its group first. Ties keep their place. React never reorders the DOM (cmdk moves nodes by hand). The keyboard walks the same order, read with the same rounding.
  - **Hiding:** items that don't match are `hidden`, not unmounted. A group with no shown items hides with its heading (state from the provider, not a CSS `:has()`, so jsdom tests see it too). Separators hide while searching, since the matches read as one list.
  - **`shouldFilter={false}`** leaves filtering to the caller (results from a server).
- **Accessibility:** the field is a `combobox` (`aria-expanded`, `aria-controls`, `aria-autocomplete="list"`, `aria-activedescendant`) controlling a `listbox` of `option`s in named `group`s, the WAI-ARIA combobox with list autocomplete. Focus never leaves the field: pressing anywhere in the list keeps it there, and the list is out of the tab order (Chrome would otherwise make the scroller a tab stop). The highlighted option is `aria-selected`. The empty message is hidden from screen readers and read from a status line next to the list instead, because a listbox may only hold options and groups, and a message that mounts with its text isn't reliably announced.
- **Keyboard:** ArrowDown/ArrowUp move (no wrap unless `loop`), Home/End jump to the ends (cmdk does; Combobox turns this off so they stay with the text), Enter runs the highlighted item, disabled items are skipped. A new search highlights its best match and scrolls to the top. Moving to a group's first row also brings its heading into view. IME composition is ignored.
- **Motion** (`.agents/rules/motion.md`):
  - **One highlight glides between rows:** Select's technique, a `layoutId` pill inside the highlighted row, `LayoutGroup id={useId()}` per list, `layoutScroll` on the scroller, the list `isolate` and the rows not stacking contexts. The keyboard and the pointer glide it on `spring.snappy`; while typing changes the list (or the list changes under it) it jumps. The jump is decided in the same render the rows move (state adjusted during render when the search changes), so the pill never glides through a reordering list.
  - **The list's height glides** as results come and go (`useGlidingHeight`, shared with Combobox): an eased tween (`duration.slow`, `ease.out`), never a spring, within the list's own max height, clipped only while it moves. It observes an inner wrapper, so it always knows where it's heading: a change mid-glide carries on from the current height instead of waiting (Popover's glide has to wait, because it has no wrapper). While it moves, the bottom fade is judged by where it's heading, so no fade flashes on the way.
  - **The empty state comes through the blur** (`blur.hidden` → `blur.shown`, `duration.base`, `ease.out`; the filter is cleared after). It leaves at once: results take its place in the same frame, and a lingering message would sit over them. It only animates after a search; a list that starts out empty is simply there.
  - **Reduced motion:** the highlight and the height jump; the empty state only fades. Nothing animates on first paint.
- **Long lists** scroll past 18rem (`max-h-72`) with Select's soft fades at the ends, outside the scroller so they never add scroll height.
- **Inside our Popover** (shadcn's Popover + Command recipe), the list's own height glide stands aside, because PopoverContent already glides its height; two glides would fight. Combobox uses Radix Popover directly, so there the list glides.
- **CommandDialog:** our Dialog (so it grows out of the button that opened it, and leaves quickly), with the Command filling a `bg-popover` window and an sr-only title and description. It sits near the top of the screen (`self-start`, `sm:mt-20`, 96px from the top like the site's search) rather than centred, so the field stays put while the list's height glides; centred, the field would drift by half of every change. No close button by default (Escape and the backdrop close it; the input row stays full width). `shortcut` toggles it with ⌘ or Ctrl plus a key: it ignores repeats, IME, Shift and Alt chords and keys another handler already took (`defaultPrevented`), and matches letters by their place too, for other keyboard layouts. Running a command and closing is the caller's choice (control `open`), as in shadcn.
- **Look:** Command is `rounded-lg bg-popover` with no border of its own (the hero adds `border shadow-md`, as a floating surface). The field is 40px (`--size-control-lg`) with a 16px search icon and a hairline under it. Rows use Select's spacing (`px-2 py-1.5 text-sm rounded-md`), icons 16px and muted, headings `text-xs` muted, shortcuts `text-xs` muted at the end (no `tracking-widest`: that class doesn't exist in our tokens, so it would look different here and in users' projects).
- **Demos:**
  - **Hero (Command menu):** inline, Suggestions (Calendar, Search emoji, disabled Calculator) and Settings (Profile, Billing, Settings with ⌘ shortcuts), a separator, keywords ("invoices" finds Billing). Held at the top of the preview, so the field doesn't move as the list glides. Preview height `lg`.
  - **Command palette:** a search-style outline Button with a ⌘J hint (a plain `kbd`; Kbd was removed on 2026-10-21) opening `CommandDialog`; choosing a command closes it. **It uses ⌘J, not ⌘K, on purpose:** the site's own search listens for ⌘K on the window and would open too (two modal dialogs at once). shadcn's docs use ⌘J for the same reason. The usage snippet and API show `shortcut="k"`.
  - **Card:** a short menu (field and two rows).
- **Tests:** roles and names (combobox, listbox, named groups), aria-controls, the shortcut left out of the value, the first item highlighted, arrows/Home/End moving aria-activedescendant and skipping disabled, no wrap, Enter and click running onSelect with focus kept in the field, filtering with groups and separators hiding, keywords and in-order matching, the best match sorted first and highlighted, the empty state and its status line, `shouldFilter={false}`, CommandDialog opening with ⌘K and Ctrl+K and closing with Escape and the shortcut, other chords ignored, axe at rest, empty and in the dialog.
- **Not built yet:**
  - `CommandLoading` (an async loading row) and cmdk's `vimBindings` (Ctrl+N/P/J/K)
  - pages inside the palette (Backspace to go back)
  - highlighting the matched part of each row (the site's search underlines it)
  - virtualisation for thousands of items (every item scores on each keystroke and the list is read from the DOM: fine for hundreds)
  - a footer of key hints in CommandDialog, like the site's search (↑↓ Navigate, ↵ Open, esc Close)
  - a larger field text on phones (`text-base`, which stops iOS zooming into it); it's `text-sm`, like Input
