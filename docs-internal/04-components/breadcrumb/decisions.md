# Breadcrumb: decisions

**Status:** published directly, without a Lab step (2026-10-16, built from the roadmap note "Where you are in the site, as a trail of links"). The page opens on a four-level trail and a deeper one with its middle collapsed into a menu, named underneath, with a Separator setting (Chevron, Slash) in the top-right corner. The index card shows one three-level trail (`preview.card`). Motion added 2026-10-19 (owner: "see if we can do anything like with motion or something"), with a second example, A trail that follows you: a small folder browser.

- **What it is:** shadcn's parts: `Breadcrumb`, `BreadcrumbList`, `BreadcrumbItem`, `BreadcrumbLink` (`asChild` for your router's Link), `BreadcrumbPage`, `BreadcrumbSeparator` and `BreadcrumbEllipsis`. The WAI-ARIA breadcrumb: a `nav` named "Breadcrumb" holding an ordered list.
- **A client component since 2026-10-19,** for the motion below. It still renders from server components: their children reach `BreadcrumbList`, which keys them with `Children.toArray` (React 19 unwraps lazy server children there). The list's `LayoutGroup` re-renders the levels once a leaving one has gone, so the rest glide to their places.
- **Hover stays the underline** (owner, 2026-10-19: "I think the underline looks good"). A gliding highlight was built the same day, Dropdown Menu's `layoutId` pill laid out sideways: mouse-only, a tint of the link's own colour at 10%, with 6px of room round each link given back by a negative margin. The owner preferred the underline, so it was taken out, and the collapsed trail's trigger went back to its own button.
- **The trail follows you:** when the levels change (an app that keeps the breadcrumb across pages), a new level **grows out of the one before it**: it slides 8px out from the left through the blur on `duration.slow` + `ease.out`, the separator first and the name `duration.instant` later, so the trail draws itself left to right. A level you leave slides back into the one before it on `duration.fast` + `ease.in`, and the rest glide to their places (`layout="position"`, `spring.snappy`). The first version slid levels in from the right on `duration.base`; the owner asked for it "coming from left" and "more smoother" (2026-10-19).
  - **The level you were on dims smoothly:** the current page's foreground colour is set on its `BreadcrumbItem` (`has-data-[slot=breadcrumb-page]:text-foreground`, `transition-colors` on `duration-slow`), not on `BreadcrumbPage`. When the page becomes a link (a different element), the level's colour fades and the link inherits it; going back up, it brightens the same way. On first paint nothing transitions.
  - `AnimatePresence initial={false}` round the levels, so nothing moves on first paint. Static trails are keyed by position, so they never animate; a trail mapped from a path animates when each level is keyed by its path (a `Fragment` holding the separator and the level, as in the demo).
  - Each level resets motion's presence context for what's inside it (`PresenceContext.Provider value={null}`). Otherwise `initial={false}` would block the entrance of anything inside, such as the collapsed menu's highlight, for good (motion.md pitfall).
  - Default `sync` mode, not `popLayout`: popLayout needs a ref on every child, which a `Fragment` can't take.
  - Not yet: right-to-left pages still grow levels from the left.
- **Reduced motion:** levels change at once.
- **Links:** muted, brightening to `foreground` on hover while the underline fades in (Button's link: the line is there all along in `transparent` and takes `currentColor`, so nothing shifts). Colour transitions only, `duration-fast` (motion.md: hover). A focus ring on each link.
- **The current page:** `BreadcrumbPage`, foreground text with `aria-current="page"`. shadcn also gives it `role="link"` and `aria-disabled`; that's left out (Biome's a11y rules flag it): a "link" that can't be focused or followed is a false promise, and `aria-current` already says what it is.
- **Separators:** `li` with `role="presentation"` and `aria-hidden`, so the list's count is the number of levels. A chevron by default, at the small icon size, flipped in right-to-left pages; pass any icon (the demo's slash) as children.
- **The collapsed middle:** `BreadcrumbEllipsis` (24px, read as "More") inside a `DropdownMenuTrigger` named "Show hidden levels", opening a Dropdown Menu of the hidden levels. The trigger brightens on hover and while open.
  - The menu's items are real links: `<DropdownMenuItem asChild><a href>`. Dropdown Menu's items support `asChild` since 2026-10-16; their label sits in `Slot.Slottable`, so the link takes the item's props and keeps the highlight inside it.
- **Demo links** are real site routes (/, /docs, /docs/installation, /components), so following one goes somewhere.
- **Tests:** the nav's name, an ordered list with only the levels as list items, links with hrefs, `asChild` styling your own link, `aria-current="page"` on the current page (and that it's not a link), opening the collapsed levels from the keyboard, a static trail still on first paint and levels coming in and going out, axe with and without the menu.
- **The folder example:** open a folder (ghost Buttons) and the trail grows; press a level to go back up. The folder list moves the way you went, like Navigation Menu's panels: going deeper, the old list slides 12px away to the left and the new one comes in from the right, row by row (0.05s apart, `duration.slow`, `ease.out`); going up, the reverse. Old and new overlap as they pass (`popLayout`, with the direction handed to the leaving list through AnimatePresence's `custom`), in a box as tall as the longest list, so the preview never changes height. It replaced a blur swap that waited for the old list to leave (owner: "more smoother"). The pressed control always goes away, so focus moves to the first folder of the new list, or in an empty folder to the level above.
- **Not built yet:** automatic collapsing by width, a max-items prop, and truncating long labels with a tooltip.
