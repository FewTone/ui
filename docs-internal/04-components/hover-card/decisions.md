# Hover Card: decisions

**Status:** published (2026-10-16), built with Popover and Tooltip as the floating-surface family. Waiting for the owner's review on the dev server.

- **What it is:** a preview of what a link points to (a person behind an @mention, a page behind a link), on Radix Hover Card. It opens when the pointer rests on the link or the link takes keyboard focus, stays open while the pointer moves onto it, and closes on Escape or a click outside. Radix makes links inside it skip Tab, and screen readers don't get the card, so the link has to make sense on its own.
- **API:** shadcn's parts, `HoverCard`, `HoverCardTrigger`, `HoverCardContent`, plus `skipDelayDuration` on `HoverCard` (the hand-over window, named like Tooltip's). `openDelay={300}` (Tooltip's; revised 2026-10-21: Radix's 700ms made the owner feel the first card was slow to load), `closeDelay={300}` (Radix's). The trigger renders an `<a>`, so it needs an `href`; `asChild` takes a Next.js Link.
- **Surface and motion:** Popover's exactly: `rounded-lg border border-border bg-popover p-4 shadow-md`, `w-64`, `z-(--z-popover)`, opening out of the link through the blur (`animate-popover-in` from `--radix-hover-card-content-transform-origin`) and closing back into it. The class string is repeated rather than imported, so installing it doesn't pull in Popover.
- **The detail: the same hand-over as Tooltip.** Once a card has been open, the next link (pointer or Tab) opens its card at once, with no delay and no animation, and the card on show goes in the same frame instead of waiting out its close delay and fading under the new one. After `skipDelayDuration` (300ms) with no card open, the next waits and animates again. Moving along names in a comment or a list of people feels quick.
  - **How:** Radix Hover Card has no provider, so a small page-wide record (the card on show, whether it's open, when it closed) lives in the module. It's only touched in event handlers and effects, so server rendering is unaffected.
  - **Opening at once:** our trigger's `onPointerEnter` and `onFocus` run before Radix's. When a card was just on show they open this one through our controlled state; Radix's own delay timer still starts and later reports "open", which is ignored because it's already open.
  - **Handing over:** opening asks the card on show to `hide()`: it turns `invisible` and closes, so Radix's closing keyframes run unseen and it unmounts.
  - **One card that moves (owner, 2026-10-21: the next card should glide, adjusting its width and height):** before the old card hides, its on-screen box is measured (mid-glide too, so a quick run along the names carries on from where it is). The new card starts on it and glides to its own place and size, Navigation Menu's shared panel: `x`/`y` for the place, `width`/`height` for the size, on `duration.base` + `ease.out` (a tween, so the size never overshoots), clipped only while moving. The offset lines up the edge Radix holds still while the size changes (the one by the link and the aligned one: the top edge and the centre for a card below a link), so Radix repositioning during the glide doesn't fight it. Its content (wrapped in one `hover-card-body` element) slides 12px in from the side it moved towards through the blur. Every inline style is cleared when it lands, or when it's stopped.
  - **Waiting for Radix's placement:** Radix parks a new card's wrapper off-screen (`translate(0, -200%)`) until floating-ui has placed it. A MutationObserver on the wrapper's style starts the glide once it's placed; the observer runs before paint, so the first frame shown is already the old card's box. The content's ref is stable (`useCallback`), so a re-render can't detach it and stop the glide. It reads the starting box without taking it: React attaches refs twice in development (Strict Mode), and taking it on the first attach left the real one with nothing to glide from, so the owner saw an instant switch (fixed 2026-10-21; the glide test renders in StrictMode to catch it).
  - With reduced motion, the next card simply appears in its place.
  - **Unmounting** while on show clears the record.
  - **First paint:** a `defaultOpen` card counts as following, so it's simply there.
- **Demo (Profiles on mentions):** "Reviewed by @maya, @theo and @ines." Each card shows initials in a `rounded-full bg-muted` circle (no Avatar yet), the name and handle, a one-line bio and a joined date with a calendar icon. Links go to `example.com` placeholders. No examples: the hero covers it.
- **Tests:** it's a link; it opens on hover and closes on leave; it opens on focus and Escape closes it, keeping focus on the link; the first card animates and the next opens well inside its 400ms delay without the opening animation while the first goes at once; the next card glides (its size held inline and clipped, with boxes stubbed, as jsdom has no layout) and leaves no inline styles behind; axe closed and open.
- **Not built yet:** an Avatar (the initials circle stands in); an arrow; a loading state for cards that fetch their content.
