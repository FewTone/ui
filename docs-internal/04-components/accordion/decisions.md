# Accordion: decisions

**Status:** built 2026-10-16 from the roadmap ("Sections that open and close with a smooth height change"), published as stable for the owner's review with the other roadmap components. Reviewed 2026-10-19 (owner: "the more good way of showing like the card style", "on hover no underline", and a variant with "the main box and under there each open close as separate boxes"). The page opens on the three looks side by side, the first section open in each (single, collapsible). The preview never changes height (owner, 2026-10-19): it's `lg`, and each demo hangs from the top of a box as tall as its tallest state (`min-h-64` for the looks with two-line answers, `min-h-72` for Several open with all three open), so opening and closing moves nothing but the accordion itself. Keep the demos' answers short (two lines in the hero, one in the example) or the reserve no longer covers them; the FAQ hero it replaced is gone, since it repeated it. The example is Several open at once (`type="multiple"`). The index card shows two closed questions in the card look (`preview.card`).

- **What it is:** sections that open and close in place, on Radix Accordion (each question is a button with `aria-expanded` inside an `h3`; the answer is a `region` named by it; Enter and Space toggle; arrow keys, Home and End move between questions). The API is shadcn's: `Accordion` (`type`, `value`, `defaultValue`, `onValueChange`, `collapsible`), `AccordionItem`, `AccordionTrigger`, `AccordionContent`. `className` on `AccordionContent` goes on the inner block, as on shadcn, so padding never fights the height animation.
- **Opening and closing run on motion** (owner, 2026-10-19: "we can improve the open close animation more good with motion and more smoother"). Until then it was Radix's measured height with the shipped CSS keyframes (2026-10-16), which had three rough edges: closing on `ease-in` stopped abruptly, so the page below snapped up; the answer faded and blurred at the same moment the box grew, half-clipped; and pressing again mid-glide restarted the keyframes from the end, so the height jumped.
  - **The height** glides on `spring.smooth` (stiffness 120, damping 20: a damping ratio of about 0.91), the preset for page sections. Its overshoot is about 0.1%, a fraction of a pixel, so the page below never bounces (motion.md now allows this one spring for height). It lands softly both ways, and a section pressed again mid-glide turns round from where it is, keeping its speed.
  - **The answer is staged against it.** Opening, the box leads and the answer follows `duration.instant` later, sharpening through the blur as it settles 6px down into place (`duration.slow`, `ease.out`); it reads as the section unfolding. Closing, the answer goes first and quickly (`duration.fast`, `ease.in`), then the empty box folds, so text is never squeezed while it's still readable. At rest the answer keeps no `filter` or `transform` (`transitionEnd`), so it adds no stacking context.
  - **How:** Radix's Content with `forceMount` and `asChild` onto a `motion.div` (the height); a second `motion.div` inside carries the answer's opacity, blur and movement, and takes `className`. Everything has `initial={false}`, so nothing animates on first paint. With reduced motion every change is instant.
  - **Clipped only while it moves:** shadcn's content is always `overflow-hidden`, which cuts off the focus ring of a link at the edge of an answer. Here it's clipped from the render that opens or closes it until the glide reaches the new state. An interrupted glide reports in too, so only the one that reached the current state counts. A section open from the start is never clipped.
  - **Closed answers stay in the page** as `hidden="until-found"`: find in page (Ctrl+F) sees their text and opens the section, and search engines read them. React 19 only writes a plain `hidden`, so a layout effect sets the value after it. On `beforematch` the section opens at once, with its height set by hand for that moment, because the browser scrolls to the match straight after the event. A disabled section stays plainly hidden, because it couldn't open. The server sends a plain `hidden`, upgraded once the page is interactive.
  - **The shipped `collapsible-open` / `-close` keyframes stay** for simpler parts (Sidebar's groups use them). JavaScript measure-and-tween is for content Radix doesn't measure (Tabs' panels).
- **The chevron turns** to point up on `spring.snappy` (a small control's spring) and back down as it closes. A `motion.span` round the icon turns, so the icon's own transform is never replaced (motion.md's SVG pitfall). `initial={false}`, so an open section's chevron is already turned on first paint. With reduced motion it turns at once.
  - **Knowing what's open:** Radix doesn't share an item's open state, so the root mirrors the value (controlled or not, single or multiple) and always passes it to Radix, as Switcher and Toggle Group do. Every change goes through one function, so a match found in the page opens a section the same way a press does, `onValueChange` included.
- **Looks** (`variant`, owner 2026-10-19):
  - **`card`, the default:** one surface with Card's recipe (`rounded-lg bg-card shadow-sm ring-1 ring-border`), a quiet `border-border` rule between sections and none under the last. Rows and answers are inset 16px (`px-4`).
  - **`separated`:** each section is its own card, Card's recipe (`rounded-lg bg-card shadow-sm ring-1 ring-border`), 8px apart (`gap-2`) with no surface behind them. The first version held them in a `bg-muted` tray; the owner dropped the tray the same day ("only card without main big BG card").
    - **The open section moves apart:** its gap to each neighbour glides from 8 to 12px (`mt-1` / `mb-1`, none at the ends) as the height does, on `duration-slow` + `ease-out` both ways (close to how `spring.smooth` lands). It reads as the one pulled out of the stack. Written as `[transition-property:margin]`, because the token check bans Tailwind's `transition-[margin]` bracket value.
  - **`plain`:** the original rows and rules, no surface and no inset, for inside something that's already a card (a Card, Sheet or Dialog).
  - questions in `text-sm font-medium`, 16px above and below; answers in `text-muted-foreground`, 16px under
  - flat: the surfaces have Card's soft shadow, the rows none; the chevron is muted and lined up with the question's first line
- **Hover:** no underline (owner, 2026-10-19; it was Button's link underline before).
  - **Card and separated:** the question's row tints to `bg-muted/50`, a fill that only fades (`duration-fast`), edge to edge. In card it takes the card's corners at the first row and at the last row while it's closed; in separated it's the section's own corners, square at the bottom while open. Their focus ring sits inside the row (`-outline-offset-(--focus-ring-width)`, as Scroll Area), so nothing pokes out of the surface and nothing needs clipping.
  - **Every look:** the chevron brightens from muted to `foreground` while the question is hovered (colour only).
- **API:** `variant` is read by every part through context (the parts' cva maps), and kept off the DOM; the root carries `data-variant`. `accordionVariants` is exported, as Button exports `buttonVariants`.
- **Tests:** buttons in headings with `aria-expanded`, a click opens its region, single closes the other and `collapsible` closes it again, Enter and Space, ArrowDown and End, multiple keeps several open, the chevron already turned on first paint and turning back as it closes, closed answers kept in the page as `hidden="until-found"` and opened by `beforematch` (with `onValueChange`), a closed section hidden again once it has folded, a disabled one plainly hidden, each look applied with `variant` kept off the DOM, axe closed and open in all three looks.
- **Not built yet:**
  - a Collapsible component (it would reuse Accordion's motion: forceMount, the `spring.smooth` height and the staged content)
  - a plus/minus icon option
