# Drawer: decisions

**Status:** new (a New badge, owner 2026-10-27; it was beta), published directly from the owner's brief (2026-10-26: "a native-feeling iOS bottom sheet… with our touch on it as a FewTone component"). ADR 0016 records the choice of Vaul and the site changes.

- **What it is:** popups that open as an iOS bottom sheet on phones (drag down to close, the page steps back, works with the keyboard) and as our centred Dialog on larger screens. shadcn's Drawer is Vaul alone; ours is responsive, so one set of parts serves both.
- **Parts follow shadcn's Drawer:** `Drawer`, `DrawerTrigger`, `DrawerClose`, `DrawerContent` (`showCloseButton`), `DrawerHeader`, `DrawerFooter`, `DrawerTitle`, `DrawerDescription`. One prop of our own: `mode` on `Drawer` (`auto`, the default, `sheet` or `dialog`).
- **Which one:** `auto` is a sheet under 768px (Tailwind's `md`) and a dialog from there. It's chosen while closed and kept while open (state that follows the media query only while closed), so turning the phone or a keyboard can't swap it mid-use. On the server and the first paint it's the dialog's trigger, which renders the same button.
- **The dialog is our Dialog:** in dialog mode every part renders Dialog's (`DialogContent`, `DialogHeader`…), keeping Dialog's slots, look and motion (it grows out of its trigger through the blur). Installing Drawer brings `dialog.tsx` along.
- **The sheet is Vaul 1.1.2** (on the same `@radix-ui/react-dialog` copy as `radix-ui`, checked in the lockfile), so focus, Escape, the backdrop and screen readers behave as in Dialog. Each rule below fixes a bug from the owner's brief:
  - **The sheet never scrolls itself.** Vaul hangs a 200%-tall filler under the sheet; a scrolling sheet scrolls into it. `DrawerContent` is a fixed shell (`flex-col`, `max-h-(--size-sheet-max)`), and its children go in a body (`data-slot="drawer-body"`) that scrolls: `grid grid-cols-1 auto-rows-max` (Tailwind's `grid-cols-1` is `minmax(0, 1fr)`, so it never grows wider than the screen), `overflow-x-hidden overflow-y-auto overscroll-contain`. Vaul only drags the sheet when that body is scrolled to its top.
  - **The keyboard is ours.** `repositionInputs={false}`, and `useKeyboard` reads `window.visualViewport` while a text field has focus: covered = `innerHeight − height − offsetTop`. The sheet's inline `bottom` lifts it by that much, and its `maxHeight` is the height left minus `--size-sheet-top-gap`. The focused field scrolls into view (`block: "nearest"`, smooth unless reduced motion) with `scroll-padding-bottom` set to the footer's measured height, so it's never hidden behind the pinned buttons.
  - **Typing never closes it.** While the keyboard is up, `handleOnly`: only the grabber drags. A pull down of more than 48px at the top of the content blurs the field first, hiding the keyboard, as iOS does.
  - **No zoom on focus:** iOS zooms into fields under 16px. Inside the sheet, on phones, fields are `text-base` (`max-md:[&_:is(input,select,textarea)]:text-base`, which outranks a field's own `text-sm`). Our Input and Textarea are `text-sm` everywhere, so they'd zoom in a page too; that's a separate fix (not made here).
  - **Sheet on a sheet:** a Drawer inside a sheet's content is Vaul's `NestedRoot`. The sheet behind steps back (scaled by 16px of its width, up 16px, on Vaul's own curve) from an effect while the inner one is open, because Vaul only does it for a press on its trigger, not when code sets `open`.
  - **Clean up (the safety net):** a quick open and close can leave `pointer-events: none`, a black body or a scaled wrapper. `unstick()` puts them back (and the body's fixed position with its scroll) once no dialog is open: when Vaul says the close has finished (`onAnimationEnd`) and when the Drawer unmounts. No polling, unlike the brief's 1s interval.
  - **Focus on open:** Vaul doesn't move focus in (moving it to the first field would raise the keyboard). Ours moves it to the sheet itself, so screen readers and the keyboard land inside it.
- **The iOS look, in our tokens:**
  - **Grabber:** Vaul's `Handle` (it stays draggable with `handleOnly`), 36×5px (`w-9 h-1.25`), 8px from the top, `rounded-full`, `bg-foreground/20`. Vaul's handle styles are unlayered CSS, so ours carry `!`.
  - **Close:** our `Button`, `secondary` `icon-sm` and `rounded-full`, an ✕ in a grey circle at `top-5 end-4` (on the title's line, as in Dialog); the header gets `pe-10` while it's shown.
  - **Shell:** `rounded-t-2xl` (18px here, 16px in a stock Tailwind project), `bg-background`, `shadow-lg`, no border. At most the screen minus the status bar (`--size-sheet-max`: `100svh − max(44px, safe area + 8px)`). On a large screen in `sheet` mode it keeps a phone's width (`max-w-lg`, centred).
  - **Footer:** sticky at the bottom of the body, full width (`-mx-6 px-6`), stacked with the last action on top (`flex-col-reverse`, as Dialog's footer on phones, so the same markup reads right in both), above the home indicator (`pb-(--size-sheet-inset-bottom)`: 16px + the safe area). Without a footer, the body has that room itself.
  - **New tokens (shipped):** `--size-sheet-top-gap`, `--size-sheet-max`, `--size-sheet-inset-bottom` (design-system §6).
- **Motion:** the sheet moves on Vaul's own curve (`cubic-bezier(0.32, 0.72, 0, 1)`, 0.5s) and drag, not our springs: it's what makes it feel native, and its drag, release and background scale all run on it. Our code uses that curve once, for the nested step back, so both sheets move together. No blur: a surface moving, as Sheet. The overlay only fades (`bg-overlay`). **Reduced motion:** the sheet fades instead of sliding (Vaul's own `fadeIn` / `fadeOut`, `duration.base`), and the page doesn't step back. Vaul doesn't check the preference itself.
- **For the page to step back** an app wraps its content once in `<div data-vaul-drawer-wrapper="">` (Vaul's drag code looks only for the `data-` form, not `vaul-drawer-wrapper`). Without it, everything else still works. The site does this in `app/layout.tsx`, with `viewport-fit=cover` so safe areas apply (the body pads itself clear of a notch sideways).
- **Demos:** Edit profile (hero: a form with a Select for what it opens as, A sheet by default so the sheet shows on a desktop too), Long content (scrolling with pinned buttons), A sheet on a sheet, and a card demo (one trigger).
- **Tests:** sheet on a phone (named, described, a grabber), dialog on a large screen, forcing either way, kept while open when the screen changes, focus on the sheet itself, sitting on a fake keyboard (visual viewport) and back, closing from its button and the footer, the nested step back, axe as a sheet and as a dialog.
- **Not built yet:** snap points, other directions (Sheet covers side panels), a non-modal sheet, a scroll fade under the header. Not verified on a real iPhone in this session: the keyboard, the zoom and the drag were checked in tests and a narrow desktop browser only.
