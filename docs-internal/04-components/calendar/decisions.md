# Calendar: decisions

**Status:** built 2026-10-16 from the roadmap ("A month view to pick dates from"), published as stable for the owner's review with the other roadmap components. Date Picker is built on it.

- **What it is:** a month view to pick a day (`mode="single"`, the default) or a range (`mode="range"`) from, with plain `Date` and `Intl` (no date library, no new npm package). One or more months side by side (`numberOfMonths`).
- **API:** react-day-picker's main props, so shadcn code moves over: `mode`, `selected`, `defaultSelected`, `onSelect(value, day)`, `month`, `defaultMonth`, `onMonthChange`, `numberOfMonths`, `disabled` (its matchers: a Date, Dates, `{ from, to }`, `{ before }`, `{ after }`, `{ dayOfWeek }`, a function, or an array of them), `weekStartsOn`, `showOutsideDays`, `fixedWeeks`, `today`, `required`, `labels`. Where it differs, and why:
  - **`min` / `max` are days** (the earliest and latest that can be picked; the calendar doesn't page past their months). In react-day-picker v9 they're a range's length in nights, and bounds are `startMonth` / `endMonth` plus `disabled`. The roadmap brief asked for `min`/`max` dates.
  - **`locale` is a language tag** (`"fr-FR"`), because names come from `Intl`; react-day-picker takes a date-fns locale. It defaults to `"en-US"`, not the runtime's language, so the server's HTML and the browser's always agree.
  - **`weekStartsOn` defaults to 0 (Sunday).** Reading it from the locale (`Intl.Locale#getWeekInfo`) isn't in every browser (Firefox), and a server and a browser that disagree would break hydration.
  - **`fixedWeeks` defaults to true** (react-day-picker: false). Six weeks every month, so the calendar never changes height between months and nothing below it jumps. With it off, the height glides (below).
  - **Range picking restarts:** the first click starts a range, the second ends it (an earlier day becomes the start), a third starts again. react-day-picker v9 moves the nearer end instead; restarting is easier to predict.
  - **`onSelect` gets the value and the clicked day,** not react-day-picker's modifiers and event.
  - **`labels`** has only what the calendar says itself: "Previous month", "Next month" and ", selected". Every date name is Intl's.
- **Keyboard and screen readers** (WAI-ARIA date grid, as in the APG date picker dialog):
  - Arrow keys by day, Up and Down by week, PageUp and PageDown by month (Shift: by year; the day is kept inside the month, so 31 October → 30 November), Home and End to the week's ends (from `weekStartsOn`). Left and right follow `direction`, so they swap on right-to-left pages. Enter and Space pick (native buttons).
  - Moving past the month's edge turns the page and the focus lands on the new day. Disabled days are skipped a day at a time in the direction of travel; a move past `min`/`max` lands on the limit.
  - **Roving tabindex:** one day is in the tab order: the one the keyboard was last on, else the picked day, else today, else the first day that can be picked. Outside days are clickable but never in the tab order (the keyboard turns the page instead).
  - Each month is a `role="grid"` named by its month (`aria-labelledby`), rows of `gridcell`s with a button inside, named by its full date from Intl ("Friday, October 16, 2026") plus ", selected" when picked (screen readers don't always read the cell's `aria-selected` while the focus is on its button; react-day-picker adds it to the label for the same reason). Picked cells are `aria-selected`; range grids are `aria-multiselectable`. Today is `aria-current="date"`.
  - **The month's name is a polite live region:** a hidden copy of the name is read when the page turns, while the drawn name (swapping through the blur) is `aria-hidden`, so a swap never reads two names.
  - **The weekday row is only drawn** (`aria-hidden`): each day's label already says its weekday. react-day-picker hides its `thead` the same way.
  - **The month buttons use `aria-disabled`, not `disabled`,** at the limits, so the focus isn't lost when you can go no further (design.md).
  - **Built from divs with ARIA roles,** not a table: the weeks lay out as rows of circles with no column gaps, and the grid slides in as one element. Biome's `useSemanticElements` / `useFocusableInteractive` are suppressed on the grid, rows and cells with the reason written beside each.
- **Today and server rendering:**
  - Today comes from `useSyncExternalStore` with a server snapshot of `null`. A server render (or a page cached at build time) can't know the visitor's today, so the server and the first browser render mark no day, then the browser marks it. It moves on at the next local midnight. `today` overrides it (tests do).
  - With no `month`, `defaultMonth` or selection, the month is today's, which the server doesn't know: the calendar holds its place invisibly (`invisible`, `aria-hidden`, a fixed placeholder month) until the browser says which month it is, rather than showing a wrong month. Pass `defaultMonth` to server-render it.
  - **Dates crossing from a server component** arrive as instants, so a day made on a UTC server can land on the day before for a visitor in the Americas. All the demos are client modules for that reason (a line in each says so); users should make dates in client code too, or pass strings.
- **Look** (neutral first, few borders):
  - Days are 32px circles in 36px cells (`--size-control-md`), `text-sm` with tabular figures. The cells touch, so the circles sit 4px apart both ways and the band runs unbroken through them (revised 2026-10-21: the owner found the spacing bad: the circles used to touch along a row and sit 4px apart down a column). The calendar has 16px of padding, 16px between the month's name, the weekday names and the days, and a month's name row as tall as a cell. Hover fills the circle with `accent`.
  - The picked day is a `primary` circle with `primary-foreground` text. A range: `primary` circles at both ends and a band between, rounded where a week breaks. The band is `primary` thinned to 10% (15% in dark), not `accent` (revised 2026-10-21: the owner found the range didn't stand out; `accent` is one grey step and nearly vanished on a card or popover). The growing band draws solid pieces and tints its layer instead, so where its caps overlap its body it never darkens. Pointing at a day inside the band deepens it (`primary/10` over it) rather than covering it in grey.
  - **Range preview:** once the start is picked, the band it would make follows the pointer (and the keyboard's focus) at half the tint (`primary/5`, 8% in dark). The day you're on already wears the end's solid `primary` circle, not the grey hover (owner, 2026-10-21), so the preview looks like the range it will be. It goes when the pointer and focus leave the days, and picking the end swaps it for the band, which grows from the start as before.
  - Today is a filled circle, `primary` at 15% (20% in dark), deepening 5% under the pointer, with `font-semibold` figures; picked or inside a range or preview, it takes that look and stays semibold (revised 2026-10-21: the owner found the 4px dot under the number looked bad, then that an `accent` fill didn't stand out from the background). Outside days and disabled days are muted; disabled days are also at the disabled opacity and take no pointer.
  - The month's name is `text-sm font-medium`, the weekdays `text-xs` muted short names ("Sun"). The month buttons are ghost `icon-sm` Buttons (composition, components.md), their chevrons flipped on right-to-left pages.
  - No border, background or shadow of its own: it sits on the page, and in Date Picker the popover gives it its surface.
- **Motion** (motion.md; nothing animates on first paint):
  - **Turning the page:** each month's grid comes through the blur and slides 12px in from the side you're going to (from the right going forward), on `duration.base` with `ease.out`, the same as a tab panel; the old days go at once. The side is mirrored on right-to-left pages. The filter is cleared when it ends, and paging again mid-entrance stops it and clears every inline style. With reduced motion it only fades.
  - **The month's name** swaps through `swap` (the old lifts away blurring, the new rises from blurred), as Copy Button's label. Opacity only with reduced motion.
  - **single: the circle travels** to the newly picked day, Radio Group's shared-mark technique. At rest each day draws its own circle. On a change, one shared circle at the calendar's level moves from the old day's centre to the new one's on `spring.snappy`, placed with `jump()` (the pitfall Radio Group hit: `set()` counts the jump as speed). Centres come from offsets, so a scaled preview doesn't double the trip. The new day's own circle waits, and hands over in the same frame when the trip ends. Its number turns light only once the circle covers it (within half a circle of its centre), so it never shows light on the page's background. A new pick mid-trip carries on from where the circle is, keeping its speed. It doesn't travel when the page turns at the same moment (a preset in another month) or with reduced motion.
  - **range: the band grows** when the end is picked: from the day picked first to the one picked last (backwards when the end was picked before the start), row by row, on one eased tween (`duration.slow`, `ease.out`; never a spring, which would overshoot the end). It's measured once, centre to centre per week, and drawn at the calendar's level as a cap where each week starts, a body that stretches (`scaleX`) and a cap riding its front, so the rounded ends never squash; only transform and opacity move. When it lands, each day's own piece takes over in the same frame (the same shapes). The circles at the ends show at once.
  - **Height:** with `fixedWeeks={false}` a month can be a week taller or shorter, and the months glide to the new height (`duration.slow`, `ease.out`, clipped only while moving), the height pattern. Inside a popover they don't: Popover glides its own height, and two glides would move in two steps.
  - **Layering:** the calendar is `isolate`; the band is `-z-20` and the circles `-z-10`, under the numbers, and no cell or button is a stacking context. Picked days have no hover fill, so the travelling circle never slides under one.
- **Demos:**
  - **Hero (Single and range):** a single and a range calendar side by side, named underneath, with Week starts (Sunday / Monday) in the top-right corner. Preview height `lg`.
  - **Card demo:** one month with a range, at half size (`scale-50`) so the whole month fits the index tile.
  - **Examples:** Two months (a range across a month's end), Disabled days and limits (weekends off, `min`/`max`), Other languages (`fr-FR`, Monday first, French `labels`).
- **Tests:** the grid's name, rows and cells; full-date names; today's `aria-current` and tab stop; a click picks and a second lets go (or keeps it with `required`); the keyboard path across a month's edge (arrows, PageDown, Shift+PageUp, Home, End, Enter) with `onMonthChange`; the month buttons and `weekStartsOn`; range picking (start, end, restart, an end before the start) and `aria-multiselectable`; disabled days and limits (not clickable, skipped by the keyboard, `aria-disabled` month buttons); two months without repeated days; a French locale; the travelling circle and the band handing over (with layout offsets stubbed, as jsdom has none); axe for a day and for a range over two months.
- **Not built yet:**
  - `mode="multiple"`
  - month and year dropdowns in the caption (react-day-picker's `captionLayout`), week numbers, a footer
  - range length limits, `excludeDisabled`, the `hidden` matcher, a `timeZone` prop, `autoFocus`
  - a vertical month list for narrow screens (two months wrap under each other instead)
- **Check by eye:** the band's caps meeting the end circles mid-growth; the today dot's position under the digits; the half-size card; a right-to-left page.
