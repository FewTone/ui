# Dropdown Menu: decisions

**Status:** published directly (2026-10-16), as part of the remaining roadmap components. The owner reviews it on the dev server with the others.

- **What it is:** a menu of actions or settings behind a button, on Radix Dropdown Menu (the WAI-ARIA menu button: Enter, Space or ArrowDown on the trigger opens it and focuses the first item; arrow keys, Home/End and typeahead inside; ArrowRight/ArrowLeft for sub-menus; Escape closes and gives focus back). The parts and props are shadcn's: `DropdownMenu`, `Portal`, `Trigger`, `Content`, `Group`, `Label`, `Item` (`variant="destructive"`, `inset`), `CheckboxItem`, `RadioGroup`, `RadioItem`, `Separator`, `Shortcut`, `Sub`, `SubTrigger`, `SubContent`. Select stays the form field for one value; this is for actions.
- **The surface is Select's:** `rounded-lg border border-border bg-popover shadow-md`, `z-(--z-popover)`, and the shipped `animate-popover-in` / `animate-popover-out` from Radix's transform origin, so it opens out of the trigger and closes back into it through the blur. It scrolls past the space left (`max-h` from Radix's available height). Sub-menus add `shadow-lg`, so they lift off the menu they overlap.
- **One highlight per menu level** (roadmap: "a highlight that glides between items"):
  - **How it moves:** Select's technique. A `motion.span` with `layoutId` renders inside the row that has it, on `spring.snappy`, scoped by `LayoutGroup id={useId()}` so two menus (or a menu and its sub-menu) never trade it. Radix focuses rows on hover and on arrow keys, so one highlight follows both.
  - **Leaving:** when the pointer leaves for a label, a separator or outside the menu, Radix gives focus back to the menu; the highlight fades out where it is (`duration.fast`, `ease.out`, opacity only: it's a fill, so no blur). Moving between rows never clears it, so it glides instead of flickering.
  - **Coming back:** onto a row while it's still fading, it glides on from there and its opacity recovers. Once it has gone, the next appearance gets a fresh `layoutId`, so it fades in at the new row instead of flying over from where it went out (the site's `RowIndicator` behaves the same way). Without this, motion keeps the last snapshot and would glide in from a stale spot.
  - **Fresh each opening:** the state lives in a provider inside the content, which Radix remounts each time.
  - **Sub-menus:** each has its own level and its own highlight. A sub-menu's trigger keeps the parent's highlight while its sub-menu is open (its open state is held by `DropdownMenuSub`, controlled or not), and lets it go if the sub-menu closes while focus is elsewhere.
  - **Stacking:** the surface is `isolate` and rows aren't stacking contexts, so the highlight passes behind every row's text (Select's 2026-10-13 pitfall).
  - **`asChild` on items (2026-10-16):** `DropdownMenuItem` (and `ContextMenuItem`) wrap their label in `Slot.Slottable`, so `<DropdownMenuItem asChild><a href>` renders a link that is the item, with the highlight inside it. Before, the highlight was a second child and Radix Slot threw. Tested.
  - **Scrolling:** the surface itself is the motion element (`asChild` on Radix's content, `layoutScroll`), so the highlight stays true in a long, scrolled menu.
  - **Reduced motion:** it jumps, and appears and goes at once.
- **Destructive items:** red text (and icon), and the highlight takes shadcn's `bg-destructive/10` (`/20` in dark) as it lands. The highlight is two fills that crossfade on opacity, so the red tint fades in and out as it glides rather than snapping at the start of the trip; colours never animate.
- **Checkbox items** draw their check in (`pathLength`, `duration.base`, `ease.out`) and erase it backwards (`duration.fast`, `ease.in`), Checkbox's motion and the same check path as Checkbox, Copy Button and Loading Button. Indeterminate draws a dash. Nothing draws when the menu opens (`initial={false}`).
- **Radio items** grow their dot from half size as it fades in (`duration-fast`, `ease-out`, CSS on Radix's always-mounted indicator), and the old one shrinks away. A fill, so no blur.
- **Marks at the end of the row**, as in Select (`pe-8`, the mark at `end-2`). shadcn puts them at the start (`pl-8`), which makes checkbox labels sit 24px right of plain items unless everything else is `inset`. Here every label lines up with no `inset`. `inset` stays for API parity: it lines a label up with items that start with an icon.
- **Sub-menu trigger:** the chevron nudges 2px towards the sub-menu while it's open (`translate-x-0.5`, `duration-fast`), mirrored in rtl. It explains where the new menu came from; it's not decoration.
- **Sub-menu placement:** in a portal, because the menu's keyframes leave a `transform` and `filter` (fill mode `both`), which would make the menu the containing block for the fixed sub-menu and clip it with the menu's scrolling. `alignOffset` defaults to -5 (the surface's padding and border), so the sub-menu's first item lines up with its trigger; `sideOffset` is 4, like the menu's.
- **Rows:** Select's spacing (`rounded-md py-1.5 ps-2 text-sm`, `pe-2` for plain items), muted icons, `text-xs` muted shortcuts with `ms-auto`. Labels are Select's (`text-xs text-muted-foreground`). No focus ring on rows: the highlight is the focus indicator, as in Select.
- **Shared with Context Menu:** the surface, rows, highlight, marks and sub-menu state are exported at the end of `dropdown-menu.tsx` (`MenuSurface`, `menuItemVariants`, `menuClasses`, `useMenuRow`, `MenuCheck`, `MenuSubContext`, `useMenuSub`), and `context-menu.tsx` imports them. Unlike Toggle Group and Switcher, which repeat their styles, the shared part here is behaviour (about 150 lines), and two copies would drift. Installing Context Menu brings Dropdown Menu with it.
- **Demos:**
  - **Hero, Account menu:** an outline Button trigger, "My account", items with shortcuts, a checkbox item, a sub-menu and a destructive Log out. The checkbox item keeps the menu open (`onSelect` with `preventDefault`), so the check is seen drawing.
  - **Examples:** Checkbox and radio items (a View menu that stays open while you choose), and Icon trigger and icons (a row's actions behind an icon button, with a destructive Delete).
  - **No card demo:** the hero is one button.
- **Tests:** the menu button's roles and `aria-expanded`; opening with Enter, Space and ArrowDown and focusing the first item; arrow keys moving the one highlight and skipping a disabled item; Enter picking and giving focus back; Escape; checkbox and radio roles and states; a sub-menu on ArrowRight/ArrowLeft with each level's highlight; the highlight going when the pointer moves onto a label and coming back on a row; axe, closed and open.
- **Not built yet:** the arrow (`DropdownMenuArrow`); a searchable menu (a command palette covers it); per-item descriptions under the label.
