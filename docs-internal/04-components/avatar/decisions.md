# Avatar: decisions

**Status:** published directly, without a Lab step (2026-10-16, built from the roadmap note "A picture or initials, alone or in a group"). The page opens on Sizes (each size with a picture and initials, and a group with "+3", named underneath), with With a name as the one example. The index card shows a large group alone (`preview.card`).

- **What it is:** a person's picture, with initials (or an icon) as the fallback. On Radix Avatar, with shadcn's parts: `Avatar`, `AvatarImage`, `AvatarFallback`, plus `AvatarGroup` and `AvatarGroupCount` (shadcn's newest set has both).
- **API:** `size` on `Avatar` (`sm | md | lg`, 24, 32 and 40px, shadcn's sizes; the default is `md`). `AvatarImage` takes Radix's props (`src`, `alt`, `onLoadingStatusChange`); `AvatarFallback` takes `delayMs`, like Radix's. `AvatarGroup` is a `div` with `role="group"`; `AvatarGroupCount` takes the size of the avatars beside it (`group-has-data-[size=…]/avatar-group:`).
- **Motion (the crafted detail): the picture comes in through the blur.**
  - Radix mounts the `img` only once it has loaded. Here, that moment the picture sharpens in from a 6px blur as it fades in (`duration.base`, `ease.out`, motion's `animate()`), over the initials. The initials stay underneath until it's fully in, then go, so nothing pops or jumps. The picture is `absolute inset-0` over the fallback, so the two never push each other.
  - **Only when the avatar was on screen without it first** (nothing animates on first paint):
    - rendered on the server: the initials were painted from the HTML, so the picture comes in after hydration even when the browser already has it;
    - loading or failed: Radix reported `loading` or `error`, which stay on screen for at least a frame.
    - A picture that's ready on the avatar's own first client render (Radix resolves a cached image in a layout effect, before the paint) just shows. So a menu or popover reopening on cached avatars doesn't replay anything.
    - Hydration is detected with `useSyncExternalStore` (the server snapshot is used while hydrating) and captured once.
  - It starts before the first paint: Radix reports `loaded` from a layout effect in the commit that adds the img, and our layout effect sets opacity 0 and starts the animation in the next synchronous commit.
  - **Clean up:** when it finishes, the inline `filter` and `opacity` are removed (ADR 0011). A change of picture or an unmount stops it.
  - **Reduced motion:** opacity only. The preference is read when the picture arrives, so changing it never replays the entrance.
  - The site preview has no Replay: a remount finds the pictures cached, and by the rule above they just show. The entrance shows on page load.
- **Why our own fallback:** Radix drops its fallback in the same render that mounts the img, so it can't stay underneath during the entrance. `AvatarFallback` is our own span, told by the picture (through context) when it's fully in. It reimplements `delayMs` the same way Radix does.
- **Accessibility:**
  - The picture's `alt` names it (`role="img"` from the img).
  - **The initials speak for the picture:** while they stand in, they carry the picture's alt (`role="img"`, `aria-label`), so a screen reader hears "Olivia Martin" whether or not the picture has loaded, never "OM". While the picture comes in over them, they're `aria-hidden`, so the name isn't read twice. With `alt=""` (the name is written beside the avatar) they're hidden too.
  - Initials without an `AvatarImage` are plain text. The demos pass `<AvatarImage src={person.picture} alt={person.name} />` even when there's no picture yet: a missing `src` is Radix's `error`, so the initials stand in with the name.
  - `AvatarGroup` is `role="group"`, named with `aria-label` ("Team, 7 people"). Biome's `useSemanticElements` suggests a `fieldset`, which is for form fields, so it's ignored on that line with the reason. The count reads as its text ("+3").
- **Look:** `rounded-full`, the fallback `bg-muted text-muted-foreground font-medium` with `text-xs` / `text-sm` / `text-base` by size. In a group, avatars overlap by 8px (`-space-x-2`, logical margins, so it works right to left) with a 2px `ring-background` between them. On a surface other than the page (a card, the site's preview tile) the ring shows as a light (or dark) outline in the page's colour; pass `*:data-[slot=avatar]:ring-card` to match a card.
- **Demo pictures:** small grey SVGs as data URIs (a moon over dunes, two peaks), so the demos work offline, built from black and white with opacity (no raw colours). Real projects pass photo URLs.
- **Demos:** Sizes (hero), With a name (`alt=""` beside a name and email), and the card.
- **Tests:** initials named by the alt while loading; the picture comes in through the blur, then the initials go and no filter is left; a cached picture on a client render shows at once without the entrance; a server-rendered avatar plays the entrance after hydration even when cached (`renderToString` + `hydrateRoot`); opacity only with reduced motion (the hook stubbed, `animate` spied); failed and missing pictures keep the named initials; `alt=""` hides them; initials alone are text; `delayMs`; the group and its count; axe while loading and once loaded. jsdom never loads images, so `window.Image` is a stand-in that loads, fails or is already cached.
- **Not built yet:** a status dot (shadcn's `AvatarBadge`); a hover lift in a group (the brief allowed it only if it explains something, such as which person a tooltip refers to; without a Tooltip pairing it would be decoration); square avatars; cut-out overlaps that work on any surface (a mask instead of the ring), which needs geometry the portable vocabulary can't express without arbitrary values.
