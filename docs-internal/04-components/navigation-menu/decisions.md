# Navigation Menu: decisions

**Status:** built 2026-10-16 from the roadmap ("A top bar with rich dropdown panels"), published as stable for the owner's review with the other roadmap components. The page opens on a docs-site header: "Getting started" (a featured Introduction card and three links with descriptions), "Components" (a two-column grid of six links) and a plain "Docs" link, with the caret. The example is Panels under their triggers (`viewport={false}`). The index card shows the closed top bar alone (`preview.card`), because the hero needs a tall box for its panel.

- **What it is:** a site's top navigation on Radix Navigation Menu: a `nav` landmark (Radix names it "Main"; the demos pass `aria-label="Documentation"` so they don't clash with the site's own "Main"), a list of disclosure buttons and links, each button opening a panel of links. Radix gives hover-open after `delayDuration` (200ms), the close delay, click/Enter/Space toggling, arrow keys between items, Tab through the open panel, Escape returning focus, and `aria-expanded` / `aria-controls`. The WAI-ARIA reference is APG's disclosure navigation menu example.
- **API:** shadcn's parts and props: `NavigationMenu` (`viewport`, default true, renders `NavigationMenuViewport` itself), `NavigationMenuList`, `NavigationMenuItem`, `NavigationMenuTrigger`, `NavigationMenuContent`, `NavigationMenuLink`, `NavigationMenuIndicator`, `NavigationMenuViewport`, and `navigationMenuTriggerStyle`. Differences:
  - `NavigationMenuLink` picks its look from where it is: in the list it gets the trigger style, inside a panel it's a row. shadcn's pattern (`asChild className={navigationMenuTriggerStyle()}`) still works; the classes merge.
  - `NavigationMenuContent` takes no `forceMount` or `asChild`: it uses both itself (below).
  - `NavigationMenuIndicator` is a caret, not shadcn's grey notch, and it renders into the viewport (below).
- **One behaviour added to Radix: ArrowDown on a closed trigger opens it and moves into the panel** (Radix only moves in when it's already open, and otherwise sends focus to the next trigger, which on a horizontal bar reads as a bug). It opens the item, then replays ArrowDown on the trigger a frame later so Radix's own entry runs (it also restores the links' tab order). Horizontal menus only.
- **Look:** neutral and flat. Triggers and top-level links are `text-sm font-medium`, muted, turning foreground on hover, open or current page, a control height (36px) with `px-3`, and no background of their own: the fill is the gliding highlight. The panel is the floating-surface family (`rounded-lg border border-border bg-popover shadow-md`, `z-(--z-popover)`), 8px under the list. The root is `h-max` (fixed 2026-10-21): in a flex row that stretches its children (the demo's `flex h-88`, or a tall header), the root grew to the row's height and the viewport, which hangs from the root's bottom edge, opened far below the triggers. Panel rows are `p-3 rounded-md`, a medium title over a muted description, filling `bg-accent` on hover (a colour transition, `duration-fast`). The featured card is a row on `bg-muted` with an icon.

## Motion
- **The highlight** is one `bg-accent` pill that glides between the top-level items on `spring.snappy` (`layoutId`, inside `LayoutGroup id={useId()}` per list). It follows the mouse only (`pointerType === "mouse"`, never on a disabled trigger); without a hover it rests on the open trigger, so keyboard and touch users see which panel is open. When neither applies it fades out where it was (`duration.fast`); back on an item while it's fading, it glides on from there; once gone, it fades in fresh where it next appears (a new `layoutId` per appearance, Dropdown Menu's approach). The list is `isolate` and the items aren't stacking contexts, so it passes behind every label (the 2026-10-13 pitfall). Its corner radius is read once as a number, so motion keeps the corners true while it changes width.
- **The viewport morphs: its width and height glide to the next panel's size.** Radix measures the active panel (`offsetWidth/Height`, after a ResizeObserver and a frame) into `--radix-navigation-menu-viewport-width/height`; the viewport sets both with `box-content` (the border sits outside the measure) and transitions `width, height` on `duration-base` + `ease-out` (the arbitrary property `[transition-property:width,height]`, since `transition-[…]` reads as an arbitrary value to the token check).
  - **Why width and height move (an exception to "only transform and opacity"):** motion.md's height pattern already lets content that changes size glide; this one surface extends it to width because the panel is a floating frame whose two dimensions change together, and a scale would distort the border, the radius and the text. It's a tween, never a spring (no overshoot), and short (`duration-base`, the same time as the new panel's entrance, so they land together). With reduced motion the CSS durations collapse, so it's instant.
  - **No glide on opening:** the viewport mounts with no size (the variables are unset, so `auto`) and gets one a frame later; `auto` → px doesn't transition, so the first size is simply there.
  - **Panels are centred in the viewport and `w-max`:** centred so a panel of another size stays put while the frame grows or shrinks round it (left-aligned panels would ride the moving left edge, sometimes against the direction of travel); `w-max` so a panel is as wide as its content and never squeezed by the frame it's about to resize. Still, panels should set their own width (`w-md` on a grid, as shadcn's demos do); free-flowing text would make a very wide panel.
  - **The viewport is centred under the list** (Radix's demo), not left-aligned (shadcn), so the panel overhangs both sides evenly. In a header at the far left of a page, a wide panel could overhang the page edge; the wrapper's `justify-center` is the one class to change.
- **Panels swap through the blur, with direction.** The new panel slides 12px in from the side you moved towards (Tabs' distance) while sharpening from 6px on `duration.base` + `ease.out`; the old one slides 12px out the other way through the blur on `duration.fast` + `ease.out`, so it clears quickly and the two barely overlap (the in-place swap timing, as `swap` uses ease-out for both sides). The sides come from Radix's `data-motion` (`from-start`, `to-end`…), which Radix flips for right-to-left pages, so start and end are the screen's left and right. The filter is cleared when the entrance ends.
  - **How the old panel stays for its exit:** Radix's Presence only waits for CSS animations, and there are no directional keyframes in the shipped tokens. So `NavigationMenuContent` passes `forceMount` while its panel is shown or leaving, and plays the motion itself with `animate()` (like Tabs). A panel left for another becomes `leaving` in the same render (state adjusted during render), stays mounted, `inert` and `pointer-events-none`, slides away, then lets go, and Presence removes it. Because the viewport reads registered panel props one render late, the panel that was shown still has `forceMount` from the render before, so it's never unmounted and remounted on its way out (a test checks it keeps its element).
  - At most the shown panel and one or two leaving ones are mounted, briefly. Only those are Radix dismissable layers, and the newest handles Escape: normally the shown one. In the 150ms after moving back to a panel that was still leaving, it's the other one; Escape still closes the menu, but focus inside the panel isn't handed back to its trigger. A panel wanted back mid-exit turns round from where it is.
  - When the menu closes, nothing slides: the panel goes with the viewport.
- **Opening and closing:** the viewport comes through the blur from its top edge (`animate-popover-in`, `origin-top`) and leaves quickly (`animate-popover-out`), the shipped keyframes. On the first opening the panel inside doesn't animate on its own.
- **The caret** (`NavigationMenuIndicator`) is a 12×6px triangle on the viewport's top edge, filled `popover` and stroked `border`, its base 1px over the viewport's border so caret and surface read as one shape. It needs to paint over the viewport, so it renders through a portal into a slot after the viewport inside the positioned wrapper (Radix's own indicator renders in the list's track, under the viewport). Its position is the open trigger's centre in offsets (layout pixels, not on-screen boxes, so zoom doesn't double the trip); it jumps there on opening and slides on `spring.snappy` between triggers (placed with `jump()`, then `animate()` on the motion value). It fades with the viewport's timing (in on `duration.fast` ease-out, out on `duration.instant` ease-in); a fill, so no blur. A ResizeObserver on the menu follows font loads without sliding. Opt-in, like shadcn's indicator: place it in `NavigationMenuList`. With `viewport={false}` it renders nothing.
  - **Fixed 2026-10-21: the caret sat at the menu's left edge.** The merged refs were a new callback every render, so on each update React detached the root's ref (null) and attached it again only after the children's layout effects. The caret measures in its own layout effect, found no root, and never moved. `useMergedRef` is now stable (`useCallback`); a test fakes the triggers' width and checks the caret lands on the open one's centre.
- **Links in a panel share one gliding highlight** (owner, 2026-10-21: "the options don't have the slider background"). Each panel holds one highlight, the same layoutId pill as the triggers' (`useHighlight`, inside a `LayoutGroup` per panel, on `spring.snappy`), in the link under the mouse, or else the one with keyboard focus; it fades out where it was when both have gone, and back on a link while fading it glides on from there. It's inside the link (`relative`, not a stacking context) and joins the panel's layer (`isolate`), so it passes behind every row's text. With `asChild` it goes inside your router's link through `Slot.Slottable`. Links lost their own `hover:bg-accent`; a link with a fill of its own (the demo's featured Introduction card, `bg-muted`) hides the highlight underneath it, so it deepens itself with `hover:bg-accent`. Mouse only for hover, so a tap goes straight to the page.
- **Opening, the links rise into place** (owner, 2026-10-21: micro-interactions): when the menu opens (not when switching panels, where the panel slides in as a whole), each link rises 6px through the blur, 0.05s apart (`duration.slow`, `ease.out`; the list stagger, with `swap`'s 6px because the rows are small), and its inline styles are cleared when it lands. Instant with reduced motion.
- **The chevron** turns over (`rotate: 180`) on `spring.snappy` while its panel is open, `initial={false}`.
- **Reduced motion:** no slide and no exit (the old panel goes at once), no blur, no rise, the frame resizes at once, the caret and both highlights jump, the chevron flips.

## Without the viewport
`viewport={false}` opens each panel under its own item as its own floating surface (start-aligned, `mt-2`, `origin-top-left`), opening and closing with the popover keyframes; no slide, no morph, no caret. Panels then live inside the list's layer (the list is `isolate` for the highlight), so the list rises to `z-(--z-popover)` while a panel is in it (`has-data-[slot=navigation-menu-content]`).

## Tests
Landmark name (Radix's "Main", or `aria-label`), `aria-expanded` on triggers, click to open and close with `onValueChange`, the panel in the viewport labelled by its trigger, Enter / Space / ArrowDown / Escape (focus back on the trigger), ArrowDown on a closed trigger, arrow keys between items and switching panels (the old panel stays inert with the same element, then goes), Tab into the panel and on through the list, one highlight in the hovered item and on the open trigger after a keyboard opening, the caret's state, `viewport={false}` panels inside their item, and axe closed and open. jsdom has no layout, so the width glide, the caret's position and the visual merge with the border are for the owner's eye. user-event doesn't send leave events to the element the pointer was over when hovering another, so the test leaves it explicitly.

## Not built yet
- vertical menus (Radix's `orientation="vertical"` works for the keys, but there's no vertical styling, and ArrowDown-to-open is horizontal only)
- `NavigationMenuSub` (nested menus inside a panel)
- a gliding highlight inside panels (rows fill on hover instead; a highlight crossing a two-column grid felt busy)
- a viewport that travels to sit under the open trigger (Stripe-style), for long lists where a centred panel ends up far from a trigger at one end
- a mobile layout: on small screens, put the links in a Sheet
