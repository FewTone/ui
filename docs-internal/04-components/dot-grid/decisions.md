# Dot Grid: decisions

**Status:** published directly, without a Lab step (2026-10-16, built from the roadmap's Backgrounds entry, "Subtle animated backgrounds for heroes and sections"). The first item of the `background` kind (`/backgrounds/dot-grid`, full-bleed preview), category Backgrounds, beside Line Grid and Gradient Drift. The page opens on a short hero over the grid (a heading, a line and a Button) with the dot spacing in a Select at the top right. The index card shows the grid alone (`preview.card`).

- **What it is:** a fine dot pattern that fills its parent from behind, for heroes and sections. A layer, not content: `absolute inset-0 -z-10 overflow-hidden pointer-events-none`, `aria-hidden`. It goes first inside a `relative isolate` section: without a stacking context on the parent, `-z-10` slips behind the parent's own background (the usage snippet and the hero show `isolate`).
- **How it's drawn:** one CSS background, a `radial-gradient` dot repeated every `size` px (default 16), with a 1px soft edge so it stays round at any size (`dotSize`, default 2px). No SVG and no per-dot elements.
- **Colour:** `currentColor`, with `text-muted-foreground` on the layer at `opacity` 0.4. So any `text-*` class recolours it (`className="text-primary"`), and it uses only shadcn's colours. Neutral, no glow.
- **The edge fade:** a radial mask (`ellipse closest-side`), solid to 30% of the way out and then easing to nothing along a half cosine. A straight ramp shows a rim where it starts; the cosine has none. `fade={false}` turns it off. The mask's `black` is alpha only, so it's not a colour on screen.
- **Server-safe:** `dot-grid.tsx` has no `"use client"`. The pattern is plain HTML and CSS, so it renders without JavaScript, and without `highlight` no JavaScript ships for it. The pointer highlight is `dot-grid-highlight.tsx`, a small client part, as Skeleton does with its sheen.
- **Motion (the crafted detail): the dots near the pointer brighten.** Chosen over a slow drift because it answers the visitor (where the pointer is) rather than moving on its own.
  - **One masked window, no per-dot JavaScript:** a round window (10 tiles from its centre) holds the same dots in `foreground`, a step brighter in dark mode and darker in light: lightness only. Its edge eases out along the same half cosine as the fade.
  - **Transform only:** the window moves with a transform, and the dots inside it are pulled back by the same amount modulo one tile, so they sit exactly on the grid's own dots wherever the window is. Both offsets are rounded to whole pixels, so the dots stay crisp and nothing is repainted per dot.
  - **The follow:** `spring.smooth`, a soft lag that reads as light rather than a cursor. Arriving, the window is placed with `jump()` (not `set()`, which would sweep it in from where it last left, the Radio Group pitfall) and fades in over `duration.slow` on `ease.out`; leaving, it fades out the same way.
  - **Where it listens:** on the grid's parent, because the grid itself ignores the pointer. Mouse only, as hover highlights are (motion.md): a touch has no hover.
  - **Zoom-safe:** pointer positions are scaled back from on-screen pixels to the layer's own (on-screen width ÷ `offsetWidth`), so it lines up inside CSS zoom or a scaled parent (the Switch pitfall).
  - **Reduced motion:** it never shows. It's still rendered, invisible, so the server and client HTML match.
  - **Clean up:** listeners removed and the fade stopped on unmount.
- **Demos:**
  - **Behind a hero (the page's hero):** the section fills the full-bleed preview (`self-stretch`, `preview.height: "lg"`), with `highlight` on and the spacing (12, 16 or 24px) in a Select at the top right.
  - **Card:** the grid alone in a `h-28` box, stretched over the card tile's padding with `-inset-5`, so the dots run to the tile's edges. It's tied to the site's tile padding (1.25rem), which is fine for a card-only demo.
- **Tests:** a layer hidden from screen readers and the pointer, behind its siblings; spacing, dot size and opacity reach the pattern; the fade on and off; a `text-*` class replaces the default colour; no highlight unless asked; a mouse move fades the window in centred on the pointer, and leaving fades it out; touch is ignored; reduced motion never shows it; axe on a section using it.
- **Not built yet:** a slow drift (rejected in favour of the pointer for now); a highlight radius or strength prop (fixed at 10 tiles); other fade shapes (towards the bottom only, a linear fade); centring the pattern in the layer (the tiles start at the top-left corner, which keeps the highlight's alignment simple).
