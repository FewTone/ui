# Sidebar: decisions

**Status:** built 2026-10-16 from the roadmap ("A collapsible app sidebar with a gliding active indicator"), published as stable for the owner's review with the other roadmap components. The page opens on a whole app shell in a 512px frame (`preview: { template: "full-bleed", height: "lg" }`): a team switcher, Platform (Dashboard, Inbox with a badge, Projects, Settings with a sub-menu), Projects, the user in the footer, the rail, and the page beside it with the trigger and a Collapse setting (to icons or off canvas). The index card shows three rows of a sidebar that stays open (`preview.card`). No examples: the hero already shows every part, and the phone sheet can only be seen at phone width.

- **What it is:** an app's main navigation beside the page, with shadcn's parts and names: `SidebarProvider`, `Sidebar` (`side`, `collapsible`), `SidebarTrigger`, `SidebarRail`, `SidebarInset`, `SidebarHeader`, `SidebarContent`, `SidebarFooter`, `SidebarGroup`, `SidebarGroupLabel`, `SidebarGroupContent`, `SidebarMenu`, `SidebarMenuItem`, `SidebarMenuButton` (`isActive`, `tooltip`, `size`, `asChild`), `SidebarMenuBadge`, `SidebarMenuSub`, `SidebarMenuSubItem`, `SidebarMenuSubButton` (a link by default, as in shadcn), `SidebarSeparator` and `useSidebar` (`state`, `open`, `setOpen`, `openMobile`, `setOpenMobile`, `isMobile`, `toggleSidebar`).
- **Sections are three parts of ours, not shadcn's `Collapsible` composition:** `SidebarMenuCollapsible` (the `li`, on Radix Collapsible), `SidebarMenuCollapsibleTrigger` (a `SidebarMenuButton` with the chevron built in) and `SidebarMenuCollapsibleContent`. The library has no Collapsible component, and building the section in means the sidebar can fold it while down to icons and hand the highlight to its row (below).
- **Behaviour:**
  - **Open state** on the provider, controlled (`open` / `onOpenChange`) or not (`defaultOpen`, true). The phone sheet keeps its own state; growing past phone size closes it.
  - **Shortcut:** ⌘B / Ctrl+B (shadcn's), as `shortcut` (a letter, or `false`). It's ignored while typing in a field or an editor (⌘B is bold there), on key repeat, and with Alt or Shift. The trigger announces it with `aria-keyshortcuts="Meta+B Control+B"`.
  - **The trigger** is a ghost `icon-sm` Button named "Toggle sidebar", with `aria-expanded` and `aria-controls` (the sidebar's id; on phones only while the sheet exists).
  - **The rail** toggles on click, with a 2px line that fades in on hover and a resize cursor. It's mouse-only: `tabIndex={-1}` and `aria-hidden`, since the trigger is the keyboard and screen reader path and shadcn's version reads as a second "Toggle sidebar" button.
  - **Landmarks:** `Sidebar` is a `nav` (named "Sidebar" unless given an `aria-label`), `SidebarInset` a `main`, with `asChild` for a page that already has one (the docs demo uses a `div`, since the docs page has its own `main`).
  - **Current page:** `isActive` sets `data-active` and `aria-current="page"`.
  - **Phones** (below 768px, `useSyncExternalStore` on a media query, desktop on the server and while hydrating; the desktop panel is `hidden md:block` so it never flashes on a phone): the sidebar opens as our `Sheet` from its side, 18rem wide, with a screen-reader title (its name) and no close button. Following a link in it closes it (a plain click; not one that opens a new tab). `collapsible="none"` stays a plain panel on phones too, as in shadcn.
  - **Down to icons, the rows keep their names:** labels are faded and clipped, not removed, so screen readers still hear "Dashboard". Tooltips name them for sight (our Tooltip, side right, through a `TooltipProvider` in the provider so they hand over down the icon column). Tooltips never open while the sidebar is open: the trigger's pointer-move and focus are cancelled before Radix sees them, rather than forcing `open={false}`, which would leave our Tooltip group thinking one is showing.
  - **A section's row while down to icons** opens the sidebar with the section showing, instead of toggling a sub-menu no one can see.
  - **Off canvas** the slid-away sidebar is `inert`, so nothing in it can be tabbed to.
- **In the flow, not fixed:** shadcn's panel is `fixed` with a spacer beside it. Ours is in the flex row, `sticky top-0 h-svh max-h-full`: in an app it stays put while the page scrolls; in a frame (the docs preview, a dashboard card) `max-h-full` keeps it to the frame, and nothing escapes it. The provider is `overflow-x-clip` (not hidden, which would break sticky), so a sidebar slid off canvas never makes the page scroll sideways. A right sidebar goes after `SidebarInset` in the markup, so the visual and focus orders agree.
- **Colours** (shadcn's `sidebar-*` colours aren't in the portable vocabulary): the panel is `bg-muted/50`, which lands on shadcn's own sidebar colours in their neutral theme (0.985 light, 0.205 dark); the page is `bg-background`, and the separation is that lightness step alone, no border. Rows are `text-muted-foreground`, brightening on hover; the current row is `font-medium text-foreground`. The current highlight is `bg-accent`, the hover one `bg-accent/60` (the site sidebar's pair).
- **Widths** are shadcn's variables, set inline on the provider: `--sidebar-width` 16rem, `--sidebar-width-icon` 3rem, and 18rem for the sheet. The four class lines that read them carry `check-tokens-ignore`: they're the component's own variables, defined by the component itself, so they work in any project (the check only knows shipped tokens).
- **Motion** (`.agents/rules/motion.md`):
  - **The crafted part: one highlight glides to the current page** on `spring.snappy`, and a second, fainter one follows the mouse (mouse only) and fades out where the pointer leaves. Moving between rows while it's still fading, it glides on; once gone, it fades in at the next row instead of flying over.
    - **Placed by numbers, not layout animations:** each row's box comes from layout offsets (`offsetLeft/Top` up to `SidebarContent`), so scrolling, the sheet's slide and CSS zoom don't throw it off (motion.md's `layoutId`-in-scroll and zoom pitfalls). Only `transform` and `opacity` move: a change of size (a sub-row is narrower and shorter) glides as a scale from the top-left corner, FLIP style, with the true size set at once.
    - **It follows the layout at once and glides only when its row changes.** A ResizeObserver on the content and its groups re-places it every frame while a section opens or the width glides; mid-glide, the spring is re-aimed instead.
    - **It writes its own style** from its motion values the moment they change. A motion component paints on the next frame, and ResizeObserver callbacks come after this frame's animation callbacks, so while the width glided the highlight trailed its row by a frame.
    - **A current page inside a folded section** (closed, or the sidebar down to icons) shows on the section's row. As Settings folds, the highlight climbs from General to Settings; as it opens, it drops back. To tell, closed sections stay in the HTML (`forceMount`, `hidden` once their keyframes end), which also keeps their links in the page for search engines.
    - **First paint:** each row draws its own background (`data-[active=true]:bg-accent`) until the highlight is placed, so the server HTML already shows the current page; in the same pre-paint pass the highlight appears and the rows drop theirs. Header and footer rows always draw their own (a colour fade), since there's no list to glide along.
  - **Narrowing to icons glides the width** on a CSS transition, `duration-slow` + `ease-in-out` (revised 2026-10-22, owner: "we can do much much better in animation and micro-interaction"; it was `ease-out`, which lurched off and crept in): the panel starts and lands softly. Never a spring, whose overshoot would bounce the page beside it. Like height, width is a sanctioned exception to transform-only here, since the page beside it has to make room. The off-canvas slide and the tall rows' 8px shift use the same curve, so everything moves as one.
  - **The icons close up into one column** (2026-10-22: down to icons, each group label used to keep its 32px as it faded, leaving a gap above every group). A label now shrinks to 16px alongside the width (`h-4`, same timing) as it leaves through the blur, and its group draws a short 16px line in its place (a fill, so it only fades, `duration-fast`, a beat after the label has gone, and first on the way back). The gliding highlight follows, since it re-places every frame while the layout changes.
  - **A badge becomes a dot** on the icon's corner down to icons, so the rail still says something's waiting (Inbox's 24): a 6px dot in the rows' quiet colour (`bg-muted-foreground`), touching the icon's top-right corner from outside rather than cut into it (a bright `bg-foreground` dot overlapping the icon read as a glitch, owner 2026-10-22), that grows from half size as it fades in, a beat after the badge has gone (`duration-base`, `ease-out`, delayed `duration-fast`), and goes first on the way back. Decorative (`aria-hidden`): the badge's count is still what's read.
  - **The trigger's icon shows the state:** our own panel icon (Lucide's PanelLeft drawn in place), whose divider slides 2.5 units in as the sidebar narrows and back out as it opens, on `spring.snappy` (the icon-that-represents-a-state pattern). Nothing moves on first paint; instant with reduced motion.
  - **The labels leave through the blur and come back through it** (ADR 0011): everything in a row after its icon, the group labels and the badges, animated together with `animate()` (leaving on `duration.fast` + `ease.in`, so the text has gone before the width closes on it; coming back on `duration.slow` + `ease.out`, keeping pace with it). The classes hold each end state; the animation only plays the change and clears its inline `opacity` and `filter` afterwards. Turned back mid-way, they carry on from where they are.
  - **Tall rows' pictures** (the team logo, the avatar) slide 8px towards the edge as a transform while the width narrows, so they end centred in the 48px column without any padding animating, and shrink to 75% (24px), so the rail's pictures weigh what its 16px icons do (2026-10-22: at 32px they looked heavy). The picture is `shrink-0`: in the 32px row its padding left 16px, and the team logo, a flex item, was squeezed into a pill (the owner's "no space"). Both transforms, on the width's timing.
  - **No scrollbar** (owner, 2026-10-22): a long list still scrolls by wheel, trackpad, touch and keyboard, but the panel shows no scrollbar (`scrollbar-width: none`, inline, since there's no stock class).
  - **Off canvas the panel slides** with the edge (`translate-x`, same tween) while the space beside it closes; no blur, since it's a surface moving.
  - **Sections** use the shipped `collapsible-open` / `collapsible-close` keyframes (Accordion's pattern), clipped only while moving. With the content kept mounted, Radix's `--radix-collapsible-content-height` lags a render behind, so the section sets `--collapsible-height` from its own `scrollHeight` right after Radix starts the keyframes. If the keyframes are missing, it settles at once rather than waiting for an `animationend` that never comes. The chevron turns 90° with a CSS transition (`duration-base`), so it never moves on first paint and collapses with reduced motion.
  - **Nothing animates on first paint** (no transition on the first style, labels skip the first run, Radix skips mount keyframes, the highlight is simply placed). **Reduced motion:** CSS durations collapse; the highlights jump and the labels switch at once.
- **Demo choices:** links that switch the preview's page (with `preventDefault`, so the docs page doesn't jump to a hash), our Dropdown Menu for the team switcher and the account menu (reworked 2026-10-22, owner: they didn't look good in a sidebar). Both open along the sidebar at the trigger's width (`w-(--radix-dropdown-menu-trigger-width)`, at least 15rem), the team menu below its row and the user menu above, so they read as part of the panel; down to icons they open beside the rail (`side="right"`, 8px off, the user menu aligned to its end), since there's no room under a 32px picture. The team menu is a radio group (the current team marked, the highlight gliding between rows): one quiet line per team: its own logo on a soft 20px `bg-muted` tile and its name (the plan stays on the trigger), then Add team with a plain plus. The first version (bordered tiles, the plan under each name, ⌘1–⌘3 hints) looked busy, and the shortcuts did nothing: the owner had them removed (2026-10-22). The user menu opens on who's signed in (avatar, name, email), then Account, Billing and Notifications with icons, and Log out in the destructive colour. Two small demo components (`TeamSwitcher`, `NavUser`) read `useSidebar()` for the placement, our Avatar (initials) in the footer, and a hint naming ⌘B or Ctrl+B in plain `kbd` text (Kbd was removed on 2026-10-21). The hero keeps the shortcut on; the card turns it off, since an index page renders many cards.
- **Tests:** the landmark and its name; the trigger's name, `aria-expanded`, `aria-controls` and `aria-keyshortcuts`; collapsing to icons and back with the trigger, ⌘B and Ctrl+B; the shortcut ignored while typing and when off; off canvas becoming `inert`; controlled `open` with `onOpenChange`; `aria-current` moving with the page; the current highlight placed on first paint instead of the row's own background; tooltips on focus only while down to icons; a section opening, closing and hiding once its keyframes end; sections folding down to icons and a section's row opening the sidebar; the badge's decorative dot and the trigger icon's divider sliding as it narrows; the rail; the phone sheet (opening, its name, the trigger's state, closing on a followed link and on Escape); the provider requirement; axe open, down to icons and as a sheet. jsdom has no `AnimationEvent`, so React listens for `webkitAnimationEnd` there; the tests fire both names.
